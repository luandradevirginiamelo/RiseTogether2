
# Rise Together

### Android Application | Software Development | Quality Assurance

Rise Together is an Android application developed as part of my final-year university project. Its purpose is to support people affected by cancer by creating a connection between patients, volunteer cancer survivors, and healthcare professionals.

The project combines mobile application development, user-focused design, and software quality assurance. My work involved developing application functionality and validating key user journeys to ensure that the system behaved as expected.

## Project Overview

People going through cancer treatment and recovery may benefit from connecting with others who have experienced similar situations.

Rise Together was designed to provide a platform where patients could connect with volunteer survivors and healthcare professionals through an Android application.

The project focused on creating a functional, accessible, and reliable mobile experience while handling important processes such as registration, authentication, user matching, and notifications.

## Project Objectives

The main objectives of Rise Together were to:

- Develop an Android application connecting cancer patients, volunteer survivors, and healthcare professionals.
- Support different user roles and their corresponding application workflows.
- Implement user registration and authentication.
- Support the process of matching patients with volunteers.
- Integrate Firebase services for application data management.
- Validate the application's functionality through structured software testing.
- Identify and address defects during development.
- Improve usability and reliability across essential user journeys.

## Core Application Functionality

### User Registration and Authentication

The application supports user registration and authentication workflows.

Testing focused on verifying that users could interact with these processes correctly, including the handling of invalid or incomplete information.

### User Roles

Rise Together was designed around different types of users, including:

- Cancer patients
- Volunteer cancer survivors
- Healthcare professionals

These roles were considered during functional testing to validate the relevant application flows.

### Patient and Volunteer Matching

An important part of the application was the process of connecting patients with volunteer survivors.

Testing included validating the matching workflow and checking that the application responded correctly to relevant user actions.

### Notifications

Notification-related functionality was included in the project's testing scope.

The goal was to verify that notification flows behaved consistently with the application's intended functionality.

### Firebase Data Management

Firebase was used to support application data storage and management.

Testing considered data integrity and the consistency of information between application interactions and the backend.

## Quality Assurance Approach

### Grey Box Testing

I used a Grey Box Testing approach during the validation process.

This combined testing from the user's perspective with an understanding of the application's internal implementation and data handling.

The approach was particularly relevant when validating Android functionality integrated with Firebase.

### Functional Testing

Functional testing was used to determine whether the application met its expected requirements.

The main areas included:

- Registration and authentication
- Input validation
- User-specific workflows
- Patient-volunteer matching
- Notifications
- Application navigation
- Firebase-related data operations

### Regression Testing

Regression testing was performed to check that application changes did not negatively affect functionality that had previously been tested.

This was important as features were developed, updated, and corrected throughout the project.

### Input Validation

Input validation testing focused on how the application handled user-provided information.

The testing considered scenarios involving:

- Missing required information
- Invalid input values
- Form validation behaviour
- Expected responses to incorrect data

### Backend Data Validation

Because the application used Firebase, testing also considered whether information was stored and handled consistently.

This helped connect the mobile user experience with the application's underlying data operations.

## Testing Workflow

My testing process followed these main stages:

1. Review the application's requirements and expected behaviour.
2. Identify important user journeys and potential failure points.
3. Design test scenarios and test cases.
4. Prepare the application and relevant test data.
5. Execute the planned tests.
6. Compare actual results with expected results.
7. Record defects and unexpected behaviour.
8. Re-test affected functionality after changes.
9. Perform regression testing where appropriate.
10. Document the testing outcomes.

## Quality Considerations

The main quality considerations for this project included:

**Functionality:** Ensuring that important application features behaved as expected.

**Reliability:** Checking the consistency of application behaviour during repeated interactions.

**Data integrity:** Validating the handling of information stored through Firebase.

**Usability:** Considering how clearly and consistently users could navigate application workflows.

**Input handling:** Verifying the application's response to incomplete or invalid information.
